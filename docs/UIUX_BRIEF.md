# UI/UX Design Brief — SecRAG

## 1. Look & feel

The visual identity is a **vault (cámara acorazada)**: a dark, technical interior fronted by an
ASCII-art **vault door** whose wheel/handle is the "open session" control. It reinforces the product's
core story — **access control and data isolation** — with a single, cohesive metaphor. Not a playful
chatbot; a security tool you *unlock*. Monospace throughout, generous whitespace, strong typographic
hierarchy, and **citations treated as first-class UI**. The emotional goal: the user should feel the
answers are *sourced, honest, and kept behind a real door*.

Principles:
- **Sources are visible, always.** Every answer shows where it came from.
- **Honesty over confidence.** Abstention is a designed, dignified state — not an error.
- **Accessible by default.** Keyboard navigable, respects `prefers-reduced-motion` (the door skips its
  open animation and reveals the form immediately).
- **Dark-only.** The vault is inherently a dark interior; a single committed theme keeps the identity
  coherent (no light variant).

## 2. Color palette

Dark steel, derived **verbatim** from the vault door prototype (`vault_ascii.html`). A single amber
accent carries all actions/links; steel tones carry structure and text. Defined once as CSS custom
properties in `frontend/app/globals.css` and mirrored as Tailwind `colors.vault.*` in
`tailwind.config.ts` — the single source of truth for the whole app.

| Token (`--…` / `vault.*`) | Hex | Role |
|------|------|------|
| `bg` | `#0a0a0c` | page background (the vault interior) |
| `plate` | `#2b2f35` | darkest surface / card tint / door plate |
| `steel-dark` | `#454c56` | borders, hollows, muted/hint text |
| `steel` | `#7d8794` | secondary text / door mid tone |
| `steel-light` | `#c7ccd2` | primary text / door highlight |
| `amber` | `#d99a3f` | accent: actions, links, focus, abstention/warning |
| `amber-bright` | `#f0b968` | accent hover |
| `danger` | `#c0563f` | delete / errors (muted red that coexists with the steel) |

Amber is used sparingly — primary actions, links, focus, and the (calm) abstention state. Citations use
a subtle `plate` surface, not amber, so they read as evidence rather than buttons. Success maps to
`steel-light` (no separate green — it would fight the palette).

## 3. Typography

- **Everything**: a monospace stack (`ui-monospace, "SF Mono", Menlo, Consolas, monospace`), set as the
  default `body`/`sans` family so the whole UI reads as a terminal/vault console.
- **Titles** use wide letter-spacing (`tracking-[0.12em]`+) for the engraved-steel feel; actions/labels
  use `tracking-[0.18em]`–`[0.28em]` and uppercase.
- **Scale**: `text-3xl` page titles, `text-sm` body/intro, `text-xs`/`text-[11px]` metadata & hints.
- Weight: 600–700 for headings, 400 for body.

## 4. Components

- **Vault door (signature component)** — `frontend/components/VaultDoor.tsx`. An ASCII door generated by
  formula (not an image/SVG); the cell aspect ratio is **measured live in the browser** so the circle
  stays round with any monospace font. Two modes: `static` (resting door, landing hero) and
  `interactive` (login) which runs the open sequence — see §6. Its tone classes
  (`c-linea/c-medio/c-hueco/c-chapa`) map to the steel tokens.
- **Buttons**: primary/secondary/destructive are all **outline** in the palette (amber, steel, danger);
  no fills except the destructive confirm hover. Clear focus-visible border.
- **Input / textarea**: rounded, visible focus, inline validation messages.
- **Conversation sidebar** (`frontend/components/ChatSidebar.tsx`): ChatGPT-style list of saved
  conversations with per-conversation token totals; **New chat**, inline **rename**, **delete**; the
  active conversation is amber-outlined. Collapses behind a ☰ toggle on mobile.
- **Message thread**: user vs assistant bubbles; the assistant bubble fills from streamed tokens (a
  blinking amber caret while streaming) and, once done, shows the **citations block** and a small
  **per-answer token count**. The header shows a **running conversation total**.
- **Stage indicator**: a single amber line under the thread naming the live pipeline step
  (classifying → retrieving → reranking → generating → checking) so the wait is legible.
- **Citation chip**: `heading · version · effective date`, monospace metadata. A signature component.
- **Abstention card**: warning-toned, calm copy ("No reliable source in the corpus"), never styled as a
  failure. Greetings/small talk get an instant conversational reply instead of abstaining.
- **Rate-limit / quota banner**: informative, non-alarming.
- **Confirmation modal**: used for irreversible actions (data deletion), danger-toned confirm button.
- **Empty states**: history empty, first-time chat.
- **Loading**: skeleton / typing indicator while retrieval+generation run.

**Abstention**
```

```

**Auth (`/login`)**: the **vault door** fills the screen. It idles with a periodic "clic" (a clean 90°
wheel turn); pressing **ABRIR** runs the open sequence and reveals a minimal access panel (email +
password, ENTER, and a link to switch between sign in / register) wired to the real auth flow.

**Account (`/account`)**: email + a clearly separated, danger-zoned "Delete my data" section.

## 6. Responsiveness & motion

- Mobile-first; content column max-width ~720px on desktop. The door uses a fluid `clamp()` font size
  so it scales down on narrow screens while staying round (live cell measurement).
- **Vault open sequence** (login): `idle` (slow "clic") → **ABRIR** → `girando` (wheel accelerates,
  bolts retract) → `abriendo` (zoom into the interior, door fades) → `dentro` (access panel fades in).
- **Reduced motion**: with `prefers-reduced-motion: reduce`, the door does not spin or zoom — ABRIR
  snaps to the open state and reveals the form immediately. A global CSS block also neutralizes other
  transitions/animations. Everything remains fully usable without motion.
